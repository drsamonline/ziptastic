ziptastic

One self-contained binary that compresses a game asset tree 20–36% smaller than xz -9, and tells you when it cannot. It recognises the container and the payload — a ZIP of PNGs, a raw CD image, a spreadsheet, a packed asset tree — undoes the compression already there, and re-compresses what is underneath. No external processes, no network, no model files.

What it does, in one transcript

A native binary cannot run in a browser, so this is a real transcript rather than a live demo — copied from a run on this machine, not written by hand.

$ ziptastic c -9 assets.zip
assets.zip  2,797,544 -> 1,284,836   -54.1%   layers=0x40  (1.2 s)

$ ziptastic d assets.zip.dr
assets.zip  1,284,836 -> 2,797,544   identical to the original

$ ziptastic c -9 --split-size 100M big.iso
big.iso  ->  big.iso.dr.001  big.iso.dr.002  big.iso.dr.003

$ ziptastic d big.iso.dr.002          # any part joins its siblings
big.iso  restored

The extension

.dr. Detection is by the CHCE magic, never by the name: a .dr renamed to .bin still decodes, and a file that is not a CHCE stream is refused. Split parts keep the HJSplit convention — archive.dr.001, archive.dr.002 — so cat and every existing split tool work unchanged.

Build it

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build        # 32 suites, ~2 minutes

CMake ≥ 3.25, Ninja and a C++20 compiler. Nothing else — brotli, brunsli, libbsc, zpaq, ppmd, preflate and liblzma are vendored and built by the same CMake run. Linux and Windows; macOS is not supported. The long form, including the traps that cost a debugging session, is in docs/BUILD.md.

What it is made of

PreprocessorsDelta, x86 and base64 transforms chosen per block, before the match finder sees the data.
Dual-resolution match finderLong matches found coarsely, short ones exactly, without a second pass over the input.
Joint optimal parserLiteral and match decisions priced together, so a cheap match never hides an expensive literal.
Per-block entropy backendsRange coding or Huffman per block, whichever the block actually favours.

What it refuses to do

No network calls. No model files to download. No external processes to shell out to. One binary in, one stream out — which is why it can be dropped into an offline pipeline without a supply chain to audit.
